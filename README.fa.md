# CampusNet

**کامپوس‌نت** یک شبکهٔ اجتماعی و اشتراک فایل با ظاهر سایبرپانکی است که روی شبکهٔ محلی (LAN) یا اینترنت اجرا می‌شود. این پروژه با Node.js و WebSocket ساخته شده و رابط فارسی و راست‌به‌چپ هم دارد.

- مخزن اصلی: https://github.com/TheROMZ52/campusnet
- راهنمای استقرار: [DEPLOY.fa.md](DEPLOY.fa.md)
- مجوز: MIT

## قابلیت‌ها

- ساخت حساب با نام کاربری و گذرواژه؛ گذرواژه‌ها با `scrypt` هش می‌شوند.
- گفت‌وگوی عمومی در کانال‌ها و پیام خصوصی دونفره.
- رمزگذاری سرتاسری پیام‌های خصوصی در مرورگر با Web Crypto، ECDH و AES-GCM.
- ارسال، دریافت، پیش‌نمایش و مدیریت فایل‌ها با نوار پیشرفت، جست‌وجو و امکان لغو انتقال.
- فهرست کاربران آنلاین، وضعیت آنلاین/دور از دسترس/مشغول و نمایش در حال تایپ بودن.
- گروه‌ها و انجمن‌ها با نقش‌های مالک، مدیر و عضو.
- صفحهٔ اطلاعیه‌ها، پست‌های اجتماعی، دنبال‌کردن کاربران، واکنش‌ها، اعلان‌ها و رسید خواندن.
- تماس صوتی دونفره از طریق WebSocket.
- پخش موسیقی از فایل‌های اشتراکی و تعیین آهنگ پروفایل.
- رابط واکنش‌گرا برای موبایل، تبلت و دسکتاپ، با تم روشن و تاریک.
- رابط فارسی و انگلیسی؛ زبان از صفحهٔ ورود یا تنظیمات قابل تغییر است.
- نقشهٔ زندهٔ کاربران متصل، ابزارهای Terminal و Monitor داخل برنامه.
- پشتیبانی از HTTPS، محدودیت دسترسی با کد مشترک و تنظیم سقف فضای فایل‌ها.

## پیش‌نیازها

- Node.js نسخهٔ ۱۸ یا جدیدتر
- npm
- برای HTTPS خودکار در اجرای محلی، OpenSSL
- برای اجرای آزمون‌های رابط کاربری، Chromium

## نصب و اجرا

مخزن را دریافت و وابستگی‌ها را نصب کنید:

```bash
git clone https://github.com/TheROMZ52/campusnet.git
cd campusnet
npm install
npm start
```

پس از اجرا، آدرس محلی در ترمینال نمایش داده می‌شود؛ معمولاً:

```text
https://localhost:3000
```

در اجرای محلی، اسکریپت شروع تنظیمات `.env` را بارگذاری می‌کند و در صورت نیاز گواهی خودامضاشدهٔ HTTPS می‌سازد. ممکن است لازم باشد هشدار گواهی را در مرورگر تأیید کنید.

### دسترسی از دستگاه‌های دیگر در شبکه

آدرس شبکه‌ای نمایش‌داده‌شده در ترمینال را از دستگاه‌های متصل به همان شبکه باز کنید. اگر اتصال برقرار نشد، فایروال سیستم و پورت انتخاب‌شده را بررسی کنید.

### اجرای آنلاین

برای میزبانی اینترنتی به محیطی نیاز دارید که Node.js و WebSocket را پشتیبانی کند و فضای ذخیره‌سازی پایدار داشته باشد؛ برای نمونه VPS یا یک سرویس میزبانی مناسب. میزبانی صرفاً ایستا مانند GitHub Pages برای اجرای سرور کافی نیست.

نمونهٔ اجرا با Docker:

```bash
docker build -t campusnet .
docker run -d -p 3000:3000 -e ACCESS_CODE=change-me -v campusnet-data:/data campusnet
```

برای انتشار عمومی، HTTPS را از طریق پراکسی یا سرویس میزبانی فعال کنید و حتماً یک کد دسترسی تنظیم کنید.

## تنظیمات محیطی

تنظیمات را می‌توان از طریق متغیرهای محیطی یا فایل `.env` تعیین کرد. مقادیر متغیرهای محیطی سیستم بر مقادیر فایل اولویت دارند.

| متغیر | مقدار پیش‌فرض | کاربرد |
| --- | --- | --- |
| `PORT` | `3000` | پورت سرور |
| `SITE_NAME` | `CampusNet` | نام نمایش‌داده‌شده در رابط |
| `ACCESS_CODE` | خالی | کد مشترک موردنیاز برای ورود؛ برای سرور عمومی توصیه می‌شود |
| `ADMIN_USERS` | خالی | نام‌های کاربری مدیر، جداشده با ویرگول |
| `ADMIN_CODE` | خالی | کد لازم برای اعطای دسترسی مدیر با فرمان `/admin` |
| `HTTPS` | خاموش | با مقدار `1`، HTTPS خودکار را فعال می‌کند |
| `TLS_CERT` | خالی | مسیر گواهی TLS دلخواه |
| `TLS_KEY` | خالی | مسیر کلید خصوصی TLS |
| `TRUST_PROXY` | خاموش | تعداد پراکسی‌های مورد اعتماد جلوی سرور |
| `MAX_FILE_MB` | `100` | حداکثر حجم هر فایل برحسب مگابایت |
| `MAX_STORAGE_MB` | `2000` | سقف کل فضای فایل‌ها برحسب مگابایت |
| `BACKUP_EVERY_HOURS` | `24` | فاصله‌ی بکاپ خودکار برحسب ساعت (`0` = خاموش) |
| `BACKUP_KEEP` | `7` | تعداد بکاپ‌های خودکاری که نگه داشته می‌شود |
| `DATA_DIR` | `./data` | مسیر داده‌ها و فایل‌های ذخیره‌شده |

نمونه در Linux و macOS:

```bash
ACCESS_CODE='your-secret-code' MAX_FILE_MB=200 npm start
```

نمونه در Windows PowerShell:

```powershell
$env:ACCESS_CODE = "your-secret-code"
npm start
```

## ابزار مدیر، حساب کاربری و بکاپ (نسخه‌ی ۰.۱۳)

مدیرها (`ADMIN_USERS`) برنامه‌ی **Admin** را در لانچر می‌بینند (برای بقیه پنهان است و هر عمل در سرور دوباره بررسی می‌شود). سه تب دارد:

- **کاربران:** جست‌وجو، تعلیق و بازگرداندن (کاربر خارج می‌شود و تا بازگردانی نمی‌تواند وارد شود)، ریست رمز و حذف. ریست رمز یک **رمز موقت** می‌دهد که فقط یک بار نشان داده می‌شود (حضوری بدهید) و هویت رمزنگاری کاربر را هم عوض می‌کند، پس او پیوی‌های قبلی‌اش را نمی‌تواند بخواند؛ بعد از ورود باید رمز جدید انتخاب کند. حذف، حساب، فایل‌ها، پست‌ها، گروه‌های متعلق به او و پیام‌های خصوصی را پاک می‌کند. مدیرها را از این پنجره نمی‌شود تعلیق، ریست یا حذف کرد.
- **سرور:** تعداد کاربران، آنلاین‌ها، فایل‌ها، فضا، حجم پوشه‌ی داده، زمان روشن بودن، نسخه، و **بستن/باز کردن ثبت‌نام** (حساب‌های موجود تأثیری نمی‌پذیرند).
- **بکاپ‌ها:** بکاپ همین حالا، دانلود یا حذف بکاپ، دانلود یک نسخه‌ی تازه.

**تنظیمات > حساب:** تغییر رمز (کلیدی که پیام‌های خصوصی را قفل می‌کند با رمز جدید دوباره قفل می‌شود و عوض نمی‌شود، پس پیوی‌های قبلی خوانا می‌مانند) و حذف حساب خودتان (با رمز؛ مدیر نمی‌تواند حساب خودش را حذف کند).

**بکاپ خودکار:** هر `BACKUP_EVERY_HOURS` ساعت یک zip از حساب‌ها، پیام‌ها، پیوی‌ها (رمزشده)، اعلان‌ها، پست‌ها، گروه‌ها، فهرست فایل‌ها و تنظیمات در `DATA_DIR/backups` ساخته می‌شود و `BACKUP_KEEP` تای آخر می‌ماند. بکاپ **خودِ فایل‌های آپلودشده را ندارد**: پوشه‌ی `DATA_DIR/uploads` را جدا کپی کنید. فقط مدیر می‌تواند بکاپ را دانلود کند.

**بازگردانی:** سرور را متوقف کنید و `node scripts/restore.js <backup.zip> --yes` را اجرا کنید (در صورت نیاز `--data DIR`). فایل‌های فعلی اول در `before-restore-<time>/` کنار گذاشته می‌شوند و چیزی پاک نمی‌شود.

## رمزگذاری و امنیت

- پیام‌های خصوصی در مرورگر فرستنده رمزگذاری می‌شوند و سرور متن آن‌ها را به‌صورت رمز‌شده نگه می‌دارد و منتقل می‌کند.
- برای قابلیت‌های مبتنی بر Web Crypto، از جمله پیام خصوصی رمزگذاری‌شده و تماس صوتی، باید از HTTPS یا `localhost` استفاده شود. در HTTP معمولی روی IP شبکهٔ محلی، این قابلیت‌ها ممکن است غیرفعال باشند.
- کانال‌های عمومی، گروه‌ها، پست‌ها، اطلاعیه‌ها و فایل‌های اشتراکی **رمزگذاری سرتاسری ندارند**؛ مدیر سرور می‌تواند به داده‌های ذخیره‌شدهٔ این بخش‌ها دسترسی داشته باشد.
- رمزگذاری پیام خصوصی، اطلاعاتی مانند اینکه چه کسی با چه کسی ارتباط دارد یا چه زمانی ارتباط برقرار شده را پنهان نمی‌کند.
- برای استقرار عمومی، HTTPS و `ACCESS_CODE` را فعال کنید، دسترسی به سرور را محدود نگه دارید و از پوشهٔ داده‌ها نسخهٔ پشتیبان تهیه کنید.
- اگر کلید خصوصی پیام‌ها با گذرواژهٔ کاربر باز نشود، بازیابی عادی گذرواژه وجود ندارد؛ گذرواژه را با دقت نگهداری کنید.

## پیش‌نمایش بدون سرور

برای دیدن رابط کاربری در حالت نمایشی، فایل `public/index.html?demo` را در مرورگر باز کنید. در این حالت شبکه و فعالیت کاربران شبیه‌سازی می‌شود؛ ورود و پیام‌ها واقعی نیستند و فایل‌ها واقعاً بارگذاری نمی‌شوند.

## آزمون‌ها

اجرای آزمون‌های سرور:

```bash
npm test
```

اجرای آزمون‌های انتهابه‌انتها در مرورگر:

```bash
npm run test:e2e
```

آزمون‌های انتهابه‌انتها به Chromium نیاز دارند. در صورت نیاز مسیر مرورگر را با متغیر `PW_CHROMIUM` مشخص کنید یا Chromium سازگار را برای `playwright-core` نصب کنید.
